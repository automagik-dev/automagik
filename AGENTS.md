# Automagik repository contract

Automagik holds the DeepSeek Harness (DSH) plugins every Automagik product builds on (the Bot team, `apps/bots-dsh`; the welcome, `apps/welcome-dsh`), the Automagik desktop app (`apps/desktop`), the Automagik Herdr pack (`herdr/`, imported from automagik-herdr with its history) and Pocket, the Android phone app (`apps/pocket/`, imported from automagik-pocket with its history; its desktop side, Pocket Link, is `herdr/mods/pocket-link`). Each part ships on its own lane of the one release (`docs/rfcs/0011-monorepo-parts-and-releases.md`).

- Bun for the repository's tooling (`scripts/`, `bun test`). The plugins run on Node like DSH (`node --test`, esbuild) and install with Bun; a DSH profile is only ever installed through DSH (`dsh plugin`, pnpm); npm only for the desktop app's Electron tooling.
- Nothing is published to npm. Plugins ship as git sources pinned to release commits and as release tarballs.
- One version for everything (`bun scripts/version.ts`, the herdr pack's `herdr/package.json` and `herdr/mods/am-sidebar/VERSION` included; Pocket's Gradle reads the root `package.json`); never edit a version by hand. One tag, `vX.Y.Z`: no per-part tags. Minor and patch stop at 999, because Pocket's versionCode is `major*1_000_000 + minor*1_000 + patch`; `version.ts` refuses more, so bump the next part up instead.
- The herdr pack (`herdr/`, its own contract in `herdr/AGENTS.md`) is plain JavaScript Herdr loads as it is: no Bun, no install, no dependencies. Two Node floors: its users' runtime (the launcher `mods/am-sidebar/bin/run.sh`, `install.sh`) is Node 22.7 or later; its tests need the newest Node 22 (their stubs use `module.registerHooks`, 22.15+) or 24, and CI runs those two. Do not add a stub fallback for older Node, and do not raise the runtime floor for the tests' sake. Its gate, from `herdr/`: `node --test 'test/*.test.mjs'`, `node --check` on `mods/*/*.js mods/*/*.mjs mods/*/bin/*.mjs scripts/*.mjs`, `shellcheck -s sh install.sh mods/am-sidebar/bin/run.sh mods/am-sidebar/bin/automagik-herdr`, `node scripts/catalog.mjs --check`, `node scripts/version.mjs check`, `node scripts/entries.mjs --check`; `herdr-app check <mod>` on a mod you changed, in a scratch app home. Its tests use temp homes and fakes (a stand-in `security` for am-quota's Keychain): never run them, the installer or `herdr-app` against a live Herdr install.
- A herdr-only merge is a herdr patch (`scripts/lane.ts`): the pack alone, no desktop build and no plugins. A release that rebuilt the pack attaches `automagik-herdr-pack-<v>.tgz` and its `.sha256` (name kept) and re-signs the rolling `herdr-lane` pointer (`pack.json` and `pack.json.sig`, `scripts/herdr-lane.ts`) with `HERDR_PACK_KEY`, the pack's own key, never `PLUGIN_LANE_KEY`. The pack's updater and `herdr/install.sh` read only that pointer, check it against `herdr/mods/am-sidebar/pack-keys.json` (install.sh's `TRUSTED_KEYS`, kept equal), then the tarball against its sha256; they never search the releases. Never print or commit a private key: tests sign with a key made per run, and the real key is made with `bun scripts/herdr-lane.ts keygen`, straight into the secret. A rotation is two phases (RFC 0011): keygen stages the new key in the slot `HERDR_PACK_SIGNER` does not name and a release ships its public key; only later does that variable switch. The pack never downgrades through the pointer: install.sh refuses one older than the installed version or recorded sequence, and the release refuses to post a lower sequence.
- Pocket Link files (`herdr/mods/pocket-link`) belong to Pocket: the pack's installer and updater never write them, and it is never in the pack's `PACK_MODS`. A Pocket Link change still goes on the herdr lane; its bridge tests (`node --test bridge/*.test.mjs find-node.test.mjs` from that folder) are `ci.yml`'s `pocket-link` job.
- Pocket (`apps/pocket/`, its own rules in `apps/pocket/AGENTS.md`) is a part with its own lane: a Pocket-only merge is a pocket patch (`scripts/lane.ts`), the app alone, no desktop build and no plugins. Gradle needs a JDK 17 or later (JBR 21 works). Run its gate from `apps/pocket/android`: `JAVA_HOME=$HOME/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home ./gradlew --no-daemon --max-workers=2 -Pkotlin.compiler.execution.strategy=in-process :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`. On a shared host, run that through the host's gate wrapper (`sh <gate.sh> ./gradlew …`). Never run `./gradlew --stop`: it stops other sessions' daemons. A machine's `local.properties` (the SDK path) stays out of git.
- A release that rebuilt Pocket attaches `automagik-pocket-<v>.apk` and `latest.json` to `vX.Y.Z`, then replaces `latest.json` on the rolling `pocket-lane` release (never a prerelease run, never to a lower versionCode). Installed phones read only that file (`pocket.updateUrl` overrides it for a fork or a test server). `pocket-lane` is created as a prerelease, never edited by hand, and never marked Latest. The APK is signed with the release key from the secrets `POCKET_SIGNING_KEYSTORE` and `POCKET_SIGNING_PASSWORD`: never print them, never regenerate the key, and never change the app ID (`ai.namastex.automagik`). Moving `latest.json` or changing its fields needs an RFC (`docs/rfcs/0011-monorepo-parts-and-releases.md`, "Pocket").
- No herdr-mod entry folder (any folder holding `mods/<name>/main.js`, `herdr/` included) may hold `layouts/`: herdr.dev skips the whole repository for one, and the skip deletes its listing. The pack's layout is its own top-level folder, `herdr-layout/` (`scripts/entries.mjs --check`, RFC 0011).
- `herdr/` is the herdr.dev Community entry's folder; do not add a `herdr-mod` or `herdr-layout` topic to this repository until the owner opens the listing.
- Generated client bundles (`client.js`) are committed: run `node scripts/build-client.mjs` in the plugin and commit the result.
- Plugin ids, routes, storage prefixes and the team's home are a public contract: installed teams keep their data there. Do not rename them.
- Omni-specific code still in the Bot team (the `omni_*` tool names, Omni as the Main Bot) belongs in Omni's plugins; move it there, not further in.
- Commits are conventional (`type(scope): description`); pull requests target `dev`.
- Do not start services, access production systems or send external messages without explicit approval.
