# Automagik repository contract

Automagik holds the DeepSeek Harness (DSH) plugins every Automagik product builds on (the Bot team, `apps/bots-dsh`; the welcome, `apps/welcome-dsh`), the Automagik desktop app (`apps/desktop`) and the Automagik Herdr pack (`herdr/`, imported from automagik-herdr with its history). Each part ships on its own lane of the one release (`docs/rfcs/0011-monorepo-parts-and-releases.md`).

- Bun for the repository's tooling (`scripts/`, `bun test`). The plugins run on Node like DSH (`node --test`, esbuild) and install with Bun; a DSH profile is only ever installed through DSH (`dsh plugin`, pnpm); npm only for the desktop app's Electron tooling.
- Nothing is published to npm. Plugins ship as git sources pinned to release commits and as release tarballs.
- One version for everything (`bun scripts/version.ts`, the herdr pack's `herdr/package.json` and `herdr/mods/am-sidebar/VERSION` included); never edit a version by hand. One tag, `vX.Y.Z`: no per-part tags.
- The herdr pack (`herdr/`, its own contract in `herdr/AGENTS.md`) is plain JavaScript Herdr loads as it is: no Bun, no install, no dependencies. Two Node floors: its users' runtime (the launcher `mods/am-sidebar/bin/run.sh`, `install.sh`) is Node 22.7 or later; its tests need the newest Node 22 (their stubs use `module.registerHooks`, 22.15+) or 24, and CI runs those two. Do not add a stub fallback for older Node, and do not raise the runtime floor for the tests' sake. Its gate, from `herdr/`: `node --test 'test/*.test.mjs'`, `node --check` on `mods/*/*.js mods/*/*.mjs mods/*/bin/*.mjs scripts/*.mjs`, `shellcheck -s sh install.sh mods/am-sidebar/bin/run.sh mods/am-sidebar/bin/automagik-herdr`, `node scripts/catalog.mjs --check`, `node scripts/version.mjs check`; `herdr-app check <mod>` on a mod you changed, in a scratch app home. Its tests use temp homes and fakes (a stand-in `security` for am-quota's Keychain): never run them, the installer or `herdr-app` against a live Herdr install.
- A herdr-only merge is a herdr patch (`scripts/lane.ts`): the pack alone, no desktop build and no plugins. A release that rebuilt the pack attaches `automagik-herdr-pack-<v>.tgz` and its `.sha256` (name kept); the pack's updater and `herdr/install.sh` take the newest release that carries them.
- Pocket Link files (`herdr/mods/pocket-link`) belong to Pocket: the pack's installer and updater never write them, and it is never in the pack's `PACK_MODS`.
- `herdr/` is the herdr.dev Community entry's folder; do not add a `herdr-mod` or `herdr-layout` topic to this repository until the owner opens the listing.
- Generated client bundles (`client.js`) are committed: run `node scripts/build-client.mjs` in the plugin and commit the result.
- Plugin ids, routes, storage prefixes and the team's home are a public contract: installed teams keep their data there. Do not rename them.
- Omni-specific code still in the Bot team (the `omni_*` tool names, Omni as the Main Bot) belongs in Omni's plugins; move it there, not further in.
- Commits are conventional (`type(scope): description`); pull requests target `dev`.
- Do not start services, access production systems or send external messages without explicit approval.
