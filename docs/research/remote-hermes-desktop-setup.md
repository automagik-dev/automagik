### SSH execution and keys

The command template in the public note uses placeholders only. Source launch is detached with a new session/nohup and redirected logs. The remote selects its listen port; Desktop reads a ready marker, allocates a local port, and authenticates through the forward. POSIX clients multiplex with ControlMaster; the non-multiplexed fallback is `ssh -N -L <local-loopback>:<local-port>:<remote-loopback>:<remote-port> ...`. Reuse requires ownership/process proof plus an authenticated probe, not merely a live PID. [Ready/tunnel](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/remote-lifecycle.ts#L1597-L1656), [reuse](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/remote-lifecycle.ts#L1760-L1777), [non-multiplexed forward](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/ssh-connection.ts#L1203-L1255).

SSH aliases are read from config/Includes and resolved with `ssh -G -- <destination>`. Explicit overrides win. An optional identity path becomes `-i`; private-key bytes are not uploaded by these inspected paths. BatchMode means interactive passwords/passphrases cannot be entered here: an agent/session must already make the key usable. An explicit Hermes executable must work; blank means autodetect, and missing/unsupported Hermes produces an error instead of installing it automatically. POSIX requires shell and Python; ownership/token-file support is capability-tested through serve help. Windows is a separate PowerShell/helper path whose helper internals were not followed. [Alias resolution](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/ssh-config.ts#L72-L172), [key argv](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/ssh-connection.ts#L458-L484), [capability/launch](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/remote-lifecycle.ts#L1122-L1166), [Windows boundary](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/windows-remote-lifecycle.ts#L752-L788).

### Secret storage conflict resolved

B found a legacy renderer/keychain contract and documentation calling shared registry secrets plaintext. A followed the active store wiring: main constructs the canonical shared store and writes through it; registry writes normalize envelopes to plaintext, and active native-token I/O also decodes toggle-produced ciphertext before persistence. Those findings agree with the guide. Legacy v1 connection-file safeStorage behavior is a narrower path; it does not establish encryption of canonical registry/native credentials. Renderer token-set/preview metadata is a separate boundary from disk encoding. [Canonical store](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/main.ts#L1970-L1976), [active write](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/main.ts#L8467-L8470), [plain registry encoding](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/gateway-connections-store.ts#L252-L283), [native encoding](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/gateway-connections-store.ts#L879-L897), [legacy policy](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/apps/desktop/electron/secret-storage-policy.ts#L13-L26), [guide](https://github.com/NousResearch/hermes-agent/blob/3bcd071226d3d605a2bb3b4f3933e7d583e189d6/website/docs/user-guide/desktop.md#L661).
