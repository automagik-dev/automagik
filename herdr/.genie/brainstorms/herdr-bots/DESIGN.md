## Problem

The owner runs about fifty coding agents in Herdr, and none of them has a lasting identity: a pane is an anonymous terminal that vanishes when it ends, so nobody can tell at a glance who is working, who is stuck and who answers to whom. He wants each project to have a permanent main bot he can talk to for the whole project, with a team of bots under it that he creates himself, each one attachable to any coding agent, briefed automatically about what matters to it, woken when a team member finishes or gets stuck, and shown in Herdr's sidebar with an Automagik character, so a human can follow the whole team without opening panes. The first version does this for projects on this computer; bots of a project on another machine are shown only (R7-2, R2-3, R3-4, R7-1).

## Approach

A bot is a saved definition in its project plus a label on whichever terminal currently plays it. Everything else the view, the briefing and the theme need is read from Herdr and herdr-core as they already are; the pack adds files, never a service.

**Group 1, foundation.** The pack is one Herdr mod folder in this repository. It starts as a byte copy of the owner's sidebar clone (`spaces-agents`, cloned from shipped `spaces` 0.1.7), so the first commit is the sidebar the owner already uses and every later change is visible as a diff. The one file left out is `sidebar-agents.json`, the owner's private rename map keyed by his machines' terminal addresses: the improved sidebar reads that map with `readTextFile` from the app home's root (`${appHome()}/sidebar-agents.json`, outside `mods/`, so saving it reloads nothing) instead of from its own folder, on every load and again on the clone's existing 15-second data timer, so the owner's hand edits there show within one tick; an absent file is an empty map, the repository ships no map, and the README's install step moves the old clone's `sidebar-agents.json` to that path. Nothing is imported and no flag is kept. The pack also leaves out the clone's `gpui-kit.d.ts` and `jsconfig.json`, which Herdr writes into a mod folder itself, and its `mod.json` is the clone's with `place` changed from `none` to `left`. Herdr's add-a-mod rule is never to overwrite a taken folder name; the pack keeps the name `spaces-agents` only because it replaces the owner's own clone, and the README makes that replacement an explicit step (move the old clone out of `mods/`, then copy the pack). A fresh Herdr has no `spaces-agents`, so nothing there is overwritten: `mod.json` places the pack on the left, where it docks beside Herdr's shipped `spaces` and `agents` sidebars on first sight; the optional `layouts/bots.json`, a copy of Herdr's shipped `main` layout with the pack in place of those two sidebars (only shipped mods plus the pack), shows it in their place after `layout.switch`. Bot definitions live in `.herdr/bots.json` at the project root, read and written with `readTextFile` and `writeTextFile` (stale-snapshot safe). Bot ids are generated unique at create, and every lookup goes project → id. A project is keyed by one rule, wherever a folder comes from (a space's folder, the folder Create picks, the folder an attached session runs in, the briefing's `$CLAUDE_PROJECT_DIR`): a folder in git belongs to its main checkout, the parent of `git rev-parse --path-format=absolute --git-common-dir` run in it, so the main checkout, every worktree and every subfolder of a repository are one project whose `.herdr/bots.json` is read and written only in the main checkout, and a worktree's committed copy of that file is never read; a folder outside git, or where `git` is missing or fails, belongs to the nearest folder at or above it that holds `.herdr/bots.json`, else to itself. Create writes the picked folder's project by that rule. The sidebar discovers definitions files by one rule: every open space's `folder`, keyed that way (git and the read run with `on: space.machine` for a remote space), so worktree spaces of one repository show its bots once, plus every project a bot was created or attached in, remembered with `setShared` so a bot whose project has no open space or live pane is still found. A remembered project is forgotten when `readTextFile` of its `.herdr/bots.json` returns null (the file is gone), never when the read rejects (the machine is unreachable). Local projects are watched with `watchFolder` on their `.herdr/` folder, so a teammate's edit arriving by git pull shows at once; remote ones are re-read on the clone's existing 15-second data timer, since `watchFolder` takes no `on`. The create form is a Herdr overlay with Herdr's own form controls: name, character and colour picker, role and instructions, coding agent from `knownAgents()`, and the project folder from `pickFolder()`. A bot's look is `{ character, colour }` with Automagik's own hash default, mirroring Automagik's `lookOf()`.

Start runs `hc run --bg` with the bot label, `herdr.space`/`herdr.tab` adoption labels, the bot's name and the project folder as cwd, on this computer only. The bot opens as a new pane in the space whose `folder` keys to the bot's project, else in the space shown now, and in that space's active tab. The hc parent is set for one purpose, the typed notes, and is always given explicitly. A main bot is started with `--no-parent`. A team member is started with `--parent <main bot's live terminal> --outlive-parent` when its main bot is live at Start (its terminal found with `hc ls --json --label <botkey>=<main bot id>`, the newest by `created_ms`, read with `hc get` for each, if two answer, since `hc ls --json` rows carry no `created_ms`), and with `--no-parent` when it is not; nothing waits on the main bot. With that parent, herdr-core itself types a note into the main bot's pane when the member becomes `blocked`, hits `error` or exits, and `--outlive-parent` keeps the member running if the main bot's terminal ends. Start never passes `--no-notify`. The bot-level tree (main bot → team members) is never read from that parent: hc sets a parent only at launch and cannot change it, so it goes stale the first time the main bot gets a new terminal. The main bot's team is the project's team-member bots in `.herdr/bots.json`, wherever their terminals are, and a team member's main bot is its project's main bot by id. This holds whether the main bot was running when a team member started, after the main bot restarts, is started again or is re-attached to another pane, and for a team member attached to a pane some other program started. The limits of the typed notes follow from the same launch-time rule and are stated, not hidden: members already running keep sending hc's notes to the main bot's old terminal after it moves, until they restart; a member started while the main bot was down sends none; and an attached member keeps the parent it was launched with, so it reaches the main bot through the briefing and its own `hc send` report rather than hc's notes, unless it was already launched under the main bot's terminal. hc parentage below a bot is unchanged: helpers a bot starts itself keep herdr-core's default parent, the bot's terminal, and end with it. Attach is `hc label` with the bot key on a live terminal of this computer. For a Claude pane, Attach first reads `hc get <t> --json` `.foreground.cwd`, the folder the session runs in, which can differ from the terminal's own `cwd` (on this host the orchestrator's terminal reports `/Users/feliperosa/workspace` and its session `/Users/feliperosa/workspace/repos/brain-v3`), and requires that folder to key to the bot's project by the rule above: the project folder, a folder inside it, or one of its worktrees. Otherwise Attach refuses and writes nothing, neither label nor hook, with a message that names both folders and the fix: create the bot in the session's project, or Start the bot fresh in its own. Claude Code reads project settings, hooks included, only from the folder its session started in (its documented settings scope, an assumption stated in Risk 14), so an attach without this check would report success and deliver no role, instructions or briefing. Start runs the same check on the folder it launches in, the bot's project, so a started bot always passes. The bot key sits outside `herdr.*` (spelling settled in the wish, for example `bot`). A pane counts as a live bot only while it carries the label and an agent is in the foreground; otherwise the bot shows as not running. One terminal plays a bot at a time: Start of a bot that is already live focuses its pane and opens nothing; Attach first removes the label from any other terminal that carries it (`hc label <old> <botkey>=`), then writes it on the chosen pane. If two terminals still carry one bot's label (a race, or a label written outside the pack), the view shows that bot once with a duplicate warning, and the view and the briefing both use the newest by `created_ms`, read with `hc get` only for the duplicates. Attaching today's orchestrator conversation is the same attach flow, run once.

**Group 2, the view.** The improved sidebar keeps the tree it already draws from herdr-core's `parent` field for every terminal that carries no bot label and for helpers under a bot. A terminal that carries a bot label is placed only by definition, never as anyone's hc child, so a team member started under the main bot's terminal is drawn once, as a team member, and never counted in the main bot's helper fold. Bot rows are placed from the definitions instead: each discovered project's main bot is a row, its team members nest under it by definition, wherever their terminals are and whether or not the main bot is running, and a live bot is found by the bot label on its terminal, which `terminals()` carries. A bot's row replaces the terminal name and app icon with the bot's name and character, and shows its kind (main bot, team member, helper). Defined bots with no live pane are merged in from their project's definitions file and marked not running. The live-bot rule reads the agent in front from `terminals()`'s `program.agent`, and the asleep pose needs the time the bot's status last changed, which `hc get` has as `status_ms` and `hc ls --json` lacks; the group's first task confirms both on this host and, for any that `terminals()` lacks, reads it with `hc get` per bot-labelled terminal on the clone's existing data timers. Turning a row asleep with no other data change takes one data wake-up per idle bot at its 10-minute mark, never a redraw loop. Per-bot folding with a count is ported from Herdr's shipped `agents` mod. Characters are Automagik's SVG drawing code; the mod computes the `color-mix()` gradient stops itself and writes plain-colour SVGs, one per character, colour and pose, under the app home outside `mods/` (a write inside a mod folder reloads it), then draws them with `image()`. Faces map to statuses as working → focused, idle → open, needs you → closed eyes with an alert motion, done → happy, failed → sad, asleep → asleep; asleep means idle for 10 minutes or more, Automagik's own threshold. The owner's status words come from herdr-core's statuses as follows: `working` → working; `blocked` → needs you in the view and stuck in the briefing; `error` → failed; `done` → done in the view and finished in the briefing; `idle` → idle, and asleep once `status_ms` is 10 minutes or more old; a live bot whose status is null (the agent has reported none yet) shows the idle pose with no asleep timer. Herdr's `Status` type in `herdr.d.ts` lists only working, blocked, done and idle, while `hc ls --json` on this host also reports `error`, so the group's first task also confirms how `error` reaches `terminals()` and, if it does not, reads it with `hc get` like the fields above. The first task of this group draws one character through `image()` on this host, and checks the `terminals()` fields above, before the roster is built out.

**Group 3, the briefing.** A per-person Claude Code hook in the project's `.claude/settings.local.json`, on `UserPromptSubmit`, runs `briefing.mjs` from the installed pack with node. It exits silently unless `HC_TERMINAL_ID` is set and that terminal carries a bot label, has a short timeout (5 seconds) and fails open. `hc ls --json` rows carry no labels, so it never tells bots from helpers with that call alone. It reads its own terminal with `hc get "$HC_TERMINAL_ID" --json` for the bot label, then its project's `.herdr/bots.json` (the project is the one `$CLAUDE_PROJECT_DIR`, the folder whose settings carry the hook, keys to by group 1's rule, the same rule the attach check used, so a session in a subfolder or a worktree reads the main checkout's file; never the terminal's `cwd`, which can differ from the agent's) for its kind, its main bot and its team; an id not defined there exits silently. Every block opens with the bot's own entry: its name, its kind, and its role with instructions, so the instructions set in the create form reach the coding agent on every turn, whether the bot was started or attached, and an edit to them in `.herdr/bots.json` applies from the next turn. `UserPromptSubmit` is the one channel because it covers both: a `SessionStart` hook or a start-time system prompt would never reach a session that was attached while already running. The instructions are capped at 4,000 characters so the team part always fits under the cap; the create form shows that limit and refuses a longer text, so nothing saved is cut unseen. For a main bot it finds each team member's terminal with `hc ls --json --label <botkey>=<id>` and lists that member's status and latest report; for a team member it finds its main bot the same way by the main bot's id, names that terminal's current address as the one to report to with `hc send` when done or stuck (the convention `hc --skill` teaches every agent), so the member's own report reaches a main bot that moved to a new terminal, and lists its own children, which are its helpers, as the `hc ls --json` rows whose `parent` is its own terminal, used only for helper counts and status. Helper counts never include a terminal that carries a bot label. The calls run in parallel; measured on this host on 2026-11-01, `hc ls --json` took 0.05 s, a `--label` query 0.02 s, and `hc get` and `hc read` under 0.01 s each, so a ten-member team (ten label queries and ten screen tails) stays well under the 5-second timeout. The latest report is the member's published status text when present, else a short tail of its screen from `hc read`; no report store is added. The block is self-contained, stays under Claude Code's 10,000-character cap, and never relies on its order among the other hooks (Brain, ai-memory, Orca, mnemosyne) already on that event. Start and attach of a Claude bot merge the hook entry, if absent, into the `.claude/settings.local.json` of the folder the session runs in (for Start the bot's project folder, its cwd; for Attach the pane's `.foreground.cwd`, which the attach check has tied to the bot's project), never into the shared `.claude/settings.json`: the entry is per person, and its command names the pack's installed `briefing.mjs` by the absolute path Start or Attach computes from `appHome()` (which honours `$HERDR_APP_HOME`) and the pack's folder under `mods/` (`command -v node >/dev/null && node "<that path>" || true`, so a machine without `node` on the agent's PATH gets no briefing and no error). Herdr exposes no call that names a mod's own folder, so Start and Attach check with `readTextFile` that `briefing.mjs` exists at the computed path before writing the entry; if the pack's folder was renamed on install (Herdr's rule when a name is taken), the check fails and the flow tells the owner, never writing a hook that silently runs nothing; its message names the fix, the README's install step: move the old `spaces-agents` clone out of `mods/`, remove the renamed copy, and copy the pack in again under its own name. When `git check-ignore` finds the file not ignored, the step appends `**/.claude/settings.local.json` to the exclude file that `git rev-parse --git-path info/exclude`, run in that folder, names (in a worktree `.git` is a file, so the path is never built by hand), which is local and never committed. If that write fails, Start or Attach warns, naming the settings file as one to keep out of commits, and continues. Whether a Claude session that is already running picks up a project hook written mid-session is unverified; a build-time check proves it on the attached orchestrator, and if the running session does not pick it up, the attach flow tells the owner to open `/hooks` once in that session to review the new hook, the fallback the README documents. The live half of check 5 needs no code of its own here: per `hc --skill`, herdr-core types a note into a parent when a child cannot report (`blocked`, `error`, exit), and a finished task (`done` while the agent keeps running) arrives as the member's own `hc send` report to the address its briefing names. Whether herdr-core also types a note on `done` is a build-time check of this group, run with the host's own herdr-core config; the member's report is the stated path either way. A host can switch every note off with `notes = false` in `~/.config/herdr-core/config.toml` (this host sets neither that nor `--no-notify`); the README names that setting.

**Group 4, the theme.** Two Herdr theme files built from Automagik's `STAGE_LIGHT` and `STAGE_DARK` for background, foreground, selection and accent, with the 16 terminal colours taken from Automagik's named colours. On its first load the mod writes them into the app home's `themes/` if absent, runs `app.theme` to select both halves, which sets the root theme of the layout shown at that first load (other layouts keep their own theme until the owner picks it there), and records that it did so with `setShared` (persisted); it never selects them again, so a theme the owner picks later is never overridden.

**Alternatives that lost.** A bot derived on the fly from template, parent and name lost because it cannot show a bot that is not running and has no persona per bot (P1, P9). An Automagik-style runtime that owns its terminals lost for the first cut because a mod cannot supervise or respawn an agent (P10). herdr-space-groups as the base lost to the owner's own sidebar (R3-1). Full frame animation lost to one pose per status (R4-2). Shipping through Automagik lost to this repository (R4-1). An access lock lost to curation (R3-2). An automatic tagger lost to explicit start and attach (R5-4). Hearing about the team only before the next turn lost to herdr-core's own typed notes plus the briefing (R7-1); a notifier of the pack's own lost to those notes, which already exist. Creating, starting and attaching on other machines lost for the first cut to showing remote bots only (R7-2).

## Simplicity Case

- **Simplest complete design:** one mod folder copied into Herdr, one definitions file per project, one label per bot pane, one hook script, two theme files. Status and helpers come from herdr-core as it is; who reports to whom comes from the definitions file (reviewer HIGH-1).
- **Added machinery:** the definitions file, because a label alone cannot show a bot that is not running (C2) or be shared with a teammate (C1); generated character SVGs, because Automagik's characters are drawing code and a bot's colour is chosen per bot (R4-3); the Claude hook, because the briefing, and with it each bot's role and instructions, must arrive with nothing typed into the pane (R2-2, reviewer HIGH-1); one launch rule for a team member's hc parent, because the owner chose to have the main bot woken as a member finishes or gets stuck, and herdr-core's existing notes do that once the parent is set (R7-1); the remembered-projects store in shared state, because a bot whose project has no open space or live pane must still show (C2), and a project leaves it when its `.herdr/bots.json` is gone (reviewer MEDIUM-6); a one-time theme selection and the shared flag recording it, because the owner chose switch-on at install and a theme he picks later must not be overridden (R5-3, C10, reviewer MEDIUM-6); one project key, the main checkout of a git folder, because a project open in several worktree spaces carries the same committed bot ids and must show its bots once (reviewer MEDIUM-2); one attach check on the folder a Claude session runs in, because a Claude bot attached outside its project would get no role, instructions or briefing while the attach reported success (reviewer HIGH-1).
- **Deferred until measured:** briefings for other coding agents (trigger: the Claude briefing ships and the owner asks for the next agent); remote create, start and attach (trigger: the owner asks for a bot in a project on another machine); respawn, schedules and memory (trigger: the owner asks for a bot to come back by itself or to remember between sessions); a history store (trigger: per-bot usage or memory needs past panes); code, merge requests and tests in the briefing (trigger: the owner widens the feed).
- **Complexity removed:** no background service, no notifier of the pack's own, no re-parenting of running members, no remote create, start or attach, no automatic tagger, no access control, no report store, no animation timer, no new image format, no change to Herdr, herdr-core or Automagik, no Herdr-pets dependency, no copy of folders of spaces, no rename-map import or flag: the map is read where the owner edits it (reviewer HIGH-2).
