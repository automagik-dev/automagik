# Automagik Herdr repository contract

Automagik Herdr is a Herdr pack: one mod folder, `mods/am-sidebar/` (the sidebar, the bot form, the briefing hook), and the `automagik-herdr` CLI in `mods/am-sidebar/bin/`. Herdr loads the folder as it is; there is no build step.

- Node 22.7 or later for everything (the installed pack has no package.json, so its `.js` files load as ESM by syntax detection; CI and releases use Node 24: `node --test 'test/*.test.mjs'`, `node scripts/version.mjs`); no Bun, no npm install, no dependencies. Files Herdr loads (`*.js`) import only `herdr`, `gpui-*` or each other; the pure ones (`model.js`, `launchArgs.js`, `models.js`, `workers.js`, `attach.js`, `formModel.js`, `release.js`, `updateCheck.js`, `spaceIconModel.js`, `meter.js`, `workerTab.js`, `migrate.js`) import none of them, so the tests and the CLI share them.
- The mod folder is named `am-sidebar` (renamed in v0.5.0, D4) and stays so: an installed layout names it, and Herdr never overwrites a taken folder. A folder is renamed only with a migration (`migrate.js`, which carries installs across the rename). The `bot` label key and `.herdr/bots.json` are a public contract too: installed teams keep their data there.
- One version for everything (`node scripts/version.mjs`: `package.json` and `mods/am-sidebar/VERSION`); never edit a version by hand. Releases are cut by CI: every push to `dev` with something new is released by `.github/workflows/release.yml` (`chore(release): vX.Y.Z`, tag, GitHub release with the pack tarball and `SHA256SUMS`, then `main` moves to it). Do not tag, release or push `main` yourself.
- Commits are conventional, checked on every pull request (`.github/workflows/commitlint.yml`): the subject matches `^(feat|fix|chore|docs|refactor|test|ci|build|perf|style|revert)(\([a-z0-9._/-]+\))?!?: .+`, and no line of the message is over 100 characters. Only `fix` makes a patch release; `chore`, `ci`, `docs` and `test` alone release nothing.
- Pull requests target `dev`. `main` holds released commits and nothing else.
- Before you push: `node --test 'test/*.test.mjs' && for f in mods/*/*.js mods/*/*.mjs mods/*/bin/*.mjs scripts/*.mjs; do node --check "$f" || exit 1; done && node scripts/version.mjs check` (what CI runs).
- Do not start services, touch a live Herdr install (`~/.config/herdr-app`, `~/.config/herdr-core`) or send external messages without explicit approval; tests use temp folders and fakes.
